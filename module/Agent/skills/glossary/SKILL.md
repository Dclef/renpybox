# 术语与专有名词

## 为什么单独立规矩

同一个词在不同条目里译法不一致，是汉化版最容易被玩家指出的问题。玩家看的是几十小时的连续文本，不是逐条孤立的句子。

## 硬规则

### 专有名词一旦确定就不改

人名、地名、组织名、技能名、道具名，在同一项目里必须始终对应同一个译法。
发现旧条目里的译法不一致时，报告给用户，不要单方面统一——用户可能有外部术语表。

### 不要翻译的东西

- 变量名、函数名、标签名（`$ var_name`、`label start`、`jump xxx`）
- 已存在的游戏内英文缩写（HP、MP、EXP、DLC、CG、UI、OST）
- 玩家自定义的名字（存档里的名字变量）
- 版本号、文件名、URL

### 需要翻译但要谨慎的

- 角色说话的口癖（"喵"、"呢"、"呀"）——保留语气，不要统一成标准书面语
- 敬称（さん/様、Mr./Mrs.）——中文没有对应层级时，用"先生/小姐"或直接省略，不要生造"桑"
- 双关、谐音、押韵——优先保住笑点，可以牺牲字面

## 判断顺序

遇到不确定的词，按这个顺序决定：

1. 项目里已经用过的译法 → 沿用
2. 用户给过术语表 → 按表
3. 该词在中文玩家圈有公认译法（如"存档点"、"二周目"）→ 用公认译法
4. 都没有 → 直译，并在回复里提醒用户"这个词我译为 X，如需统一请在术语表里加一条"

## 报告格式

发现不一致时，不要自己改，列出：

```
词条：<原文>
出现译法：A（12 处）、B（3 处）
建议：统一为 A
```

让用户决定。

## 不要做的事

- 不要为了"好听"把专有名词意译成完全不同的词
- 不要在没看到全部上下文时批量替换
- 不要把日式汉字词直接当中文用（"大丈夫"、"勉强"、"邪魔"）
